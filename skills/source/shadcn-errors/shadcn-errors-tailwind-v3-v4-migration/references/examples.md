### v4 (the equivalent file: NONE)

Delete `tailwind.config.js`. The container settings, color extension, border-radius scale, keyframes, animation timings, and the animate plugin are ALL replaced by the `@theme inline` block in `globals.css` plus `@import "tw-animate-css";`. If you need to keep a JS config for a non-trivial extension, add this single line at the top of `globals.css`:

```css
@config "../../tailwind.config.js";
```

But for stock shadcn projects this is not needed and the file should be removed.

## 4. `vite.config.ts` (Vite projects only)

### v3 (full file)

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import path from "path";

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { "@": path.resolve(__dirname, "./src") },
  },
});
```

### v4 (full file, preferred)

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import path from "path";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: { "@": path.resolve(__dirname, "./src") },
  },
});
```

Add the `@tailwindcss/vite` import and call `tailwindcss()` in the `plugins` array. Vite v4 projects do NOT need `postcss.config.js` at all when using the Vite plugin.

## 6. Side-by-side: ring utility on Button focus

### v3 Button focus class (excerpt)

```tsx
const buttonVariants = cva(
  "inline-flex items-center justify-center whitespace-nowrap rounded-md text-sm font-medium ring-offset-background transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 disabled:pointer-events-none disabled:opacity-50",
  { /* variants ... */ }
);
```

### v4 Button focus class (excerpt)

```tsx
const buttonVariants = cva(
  "inline-flex items-center justify-center gap-2 whitespace-nowrap rounded-md text-sm font-medium transition-all disabled:pointer-events-none disabled:opacity-50 [&_svg]:pointer-events-none [&_svg:not([class*='size-'])]:size-4 [&_svg]:shrink-0 outline-none focus-visible:border-ring focus-visible:ring-ring/50 focus-visible:ring-[3px] aria-invalid:ring-destructive/20 dark:aria-invalid:ring-destructive/40 aria-invalid:border-destructive",
  { /* variants ... */ }
);
```

Three v4 shifts visible in the diff:

1. `focus-visible:ring-2` (v3) became `focus-visible:ring-[3px]` (v4) so the visual ring thickness is preserved against the new v4 default of 1px.
2. `ring-offset-background` and `ring-offset-2` (v3) are gone; v4 relies on the `border-ring` + `ring/50` pattern instead.
3. `outline-none` (v3, was a hard reset) was renamed; the v4 equivalent is `outline-hidden`, but shadcn v4 uses plain `outline-none` because v4 still parses the legacy class name (it just maps to a different rule).

ALWAYS re-pull Button via `pnpm dlx shadcn@latest add button --overwrite` after Tailwind migration rather than hand-editing these classes.

## 7. Side-by-side: dark mode toggle wiring

### v3 ThemeProvider + mode-toggle

```tsx
// app/providers.tsx
"use client";
import * as React from "react";
import { ThemeProvider as NextThemesProvider } from "next-themes";
import type { ThemeProviderProps } from "next-themes/dist/types";

export function ThemeProvider({ children, ...props }: ThemeProviderProps) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>;
}

// app/layout.tsx
<html lang="en" suppressHydrationWarning>
  <body>
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>
      {children}
    </ThemeProvider>
  </body>
</html>
```

### v4 ThemeProvider + mode-toggle (UNCHANGED)

```tsx
// app/providers.tsx
"use client";
import * as React from "react";
import { ThemeProvider as NextThemesProvider } from "next-themes";

export function ThemeProvider({
  children,
  ...props
}: React.ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>;
}

// app/layout.tsx : IDENTICAL to v3
```

The user-facing wiring is identical: `attribute="class"`, `suppressHydrationWarning` on `<html>`, the ThemeProvider wrapper, the `useTheme()` hook in the mode-toggle dropdown. The only change is on the Tailwind side: v3 reads `darkMode: ['class']` from `tailwind.config.js`; v4 reads `@custom-variant dark (&:is(.dark *));` from `globals.css`. The toggle DOM behavior (adding `class="dark"` to `<html>`) is unchanged.

## 8. The mode-toggle component (unchanged across versions)

```tsx
"use client";
import { Moon, Sun } from "lucide-react";
import { useTheme } from "next-themes";
import { Button } from "@/components/ui/button";
import { DropdownMenu, DropdownMenuContent, DropdownMenuItem, DropdownMenuTrigger } from "@/components/ui/dropdown-menu";

export function ModeToggle() {
  const { setTheme } = useTheme();
  return (
    <DropdownMenu>
      <DropdownMenuTrigger asChild>
        <Button variant="outline" size="icon">
          <Sun className="h-[1.2rem] w-[1.2rem] rotate-0 scale-100 transition-all dark:-rotate-90 dark:scale-0" />
          <Moon className="absolute h-[1.2rem] w-[1.2rem] rotate-90 scale-0 transition-all dark:rotate-0 dark:scale-100" />
          <span className="sr-only">Toggle theme</span>
        </Button>
      </DropdownMenuTrigger>
      <DropdownMenuContent align="end">
        <DropdownMenuItem onClick={() => setTheme("light")}>Light</DropdownMenuItem>
        <DropdownMenuItem onClick={() => setTheme("dark")}>Dark</DropdownMenuItem>
        <DropdownMenuItem onClick={() => setTheme("system")}>System</DropdownMenuItem>
      </DropdownMenuContent>
    </DropdownMenu>
  );
}
```

This file is identical in v3 and v4 shadcn projects. The migration does NOT touch consumer-facing dark mode logic.

## 9. Chart color migration (recharts)

### v3 chartConfig

```tsx
const chartConfig = {
  desktop: { label: "Desktop", color: "hsl(var(--chart-1))" },
  mobile: { label: "Mobile", color: "hsl(var(--chart-2))" },
};
```

### v4 chartConfig

```tsx
const chartConfig = {
  desktop: { label: "Desktop", color: "var(--chart-1)" },
  mobile: { label: "Mobile", color: "var(--chart-2)" },
};
```

The `hsl()` wrapper is removed because v4 tokens are already valid CSS color values (oklch). Forgetting this rewrite produces transparent or zero-color chart fills.
