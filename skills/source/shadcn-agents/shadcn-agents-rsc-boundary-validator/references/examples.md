# Examples : RSC Boundary Validator

Two worked traces : a broken App Router project, and the corrected
version. Plus a canonical server-shell + client-island example used as
the reference shape for verdict reports.

All code targets Next.js App Router 15.x + React 19 + shadcn ui
evergreen-2026, verified against
https://nextjs.org/docs/app/building-your-application/rendering/composition-patterns
and https://ui.shadcn.com/docs/components-json. Last verified : 2026-05-19.

---

## 1. BROKEN : App Router Project with 4 Defects

### 1.1 The source tree

```
my-app/
  components.json         { "rsc": true, "tsx": true, ... }
  app/
    layout.tsx            "use client"           <-- DEFECT 1 (rule 3)
    page.tsx              (server)
    products/
      page.tsx            (server, passes onClick to client child)   <-- DEFECT 4 (rule 6)
  components/
    ui/
      card.tsx            (server, RSC-safe)
      dialog.tsx          (server)               <-- DEFECT 2 (rule 2)
      sheet.tsx           (server)               <-- DEFECT 2 (rule 2)
    product-actions.tsx   "use client"
```

### 1.2 The offending file bodies

```tsx
// app/layout.tsx (DEFECT 1)
"use client"                                           // <-- WRONG : kills RSC for every page
import { ThemeProvider } from "next-themes"            // <-- DEFECT 3 (rule 5)
import "./globals.css"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}
```

```tsx
// components/ui/dialog.tsx (DEFECT 2)
// Generated by `shadcn add dialog` but the directive was hand-stripped after a merge.
// First non-blank line :
import * as React from "react"
import * as DialogPrimitive from "@radix-ui/react-dialog"
// ... rest of the Radix Dialog wrapper
```

Hydration crash at runtime :
`Error: useState is not a function`. The Radix Dialog calls
`React.useState` during its own initialisation ; without `"use client"`
the file ships through the server bundle where the hook is unavailable.

```tsx
// app/products/page.tsx (DEFECT 4)
import { ProductActions } from "@/components/product-actions"     // client
import { db } from "@/lib/db"

export default async function ProductsPage() {
  const products = await db.product.findMany()
  return (
    <ul>
      {products.map((p) => (
        <ProductActions
          key={p.id}
          productId={p.id}
          onDelete={() => db.product.delete({ where: { id: p.id } })}   // <-- WRONG
        />
      ))}
    </ul>
  )
}
```

Build error :
`Error: Functions cannot be passed directly to Client Components
unless you explicitly expose it by marking it with "use server".`

### 1.3 Validator verdict on the broken tree

```
RSC Boundary Audit : my-app

[1] components.json rsc flag       :  PASS  (rsc:true matches framework=app-router)
[2] Client primitive directives    :  FAIL
      MISSING in components/ui/dialog.tsx
      MISSING in components/ui/sheet.tsx
[2b] RSC-safe over-clientification :  PASS
[3] Layout/page/template not client:  FAIL
      OVER-CLIENT app/layout.tsx
[4] Directive well-formedness      :  PASS  (the directives that DO exist are well-formed)
[5] Provider wrappers              :  FAIL
      PROVIDER in server file app/layout.tsx (next-themes ThemeProvider direct import)
[6] Boundary props                 :  FAIL
      app/products/page.tsx:12 inline arrow onDelete to <ProductActions>

Verdict : FAIL. 4 critical defects + 0 warnings.
Run remediation : see shadcn-impl-rsc-vs-client-boundaries (B10).
```

The validator surfaces all four defects in a single pass.

## 2. CORRECT : Same Project After Fixing All Four Defects

### 2.1 The corrected source tree

```
my-app/
  components.json         { "rsc": true, "tsx": true, ... }
  app/
    layout.tsx            (server, imports the wrapper)
    page.tsx              (server)
    products/
      page.tsx            (server, hosts ProductActions, no onDelete prop)
  components/
    theme-provider.tsx    "use client"
    product-actions.tsx   "use client"
    ui/
      card.tsx            (server)
      dialog.tsx          "use client"
      sheet.tsx           "use client"
  app/products/
    actions.ts            "use server"           (Server Actions)
```

### 2.2 The corrected file bodies

```tsx
// app/layout.tsx (server)
import { ThemeProvider } from "@/components/theme-provider"
import "./globals.css"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}
```

```tsx
// components/theme-provider.tsx
"use client"
import { ThemeProvider as NextThemesProvider } from "next-themes"
import type * as React from "react"

export function ThemeProvider({
  children,
  ...props
}: React.ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>
}
```

```tsx
// components/ui/dialog.tsx (the directive restored by `shadcn add dialog --overwrite`)
"use client"
import * as React from "react"
import * as DialogPrimitive from "@radix-ui/react-dialog"
// ... rest of the Radix Dialog wrapper
```

```ts
// app/products/actions.ts
"use server"
import { db } from "@/lib/db"

export async function deleteProductAction(productId: string) {
  await db.product.delete({ where: { id: productId } })
}
```

```tsx
// app/products/page.tsx (server)
import { ProductActions } from "@/components/product-actions"
import { deleteProductAction } from "./actions"
import { db } from "@/lib/db"

export default async function ProductsPage() {
  const products = await db.product.findMany()
  return (
    <ul>
      {products.map((p) => (
        <ProductActions
          key={p.id}
          productId={p.id}
          deleteAction={deleteProductAction}   // <-- OK : a "use server" function is allowed
        />
      ))}
    </ul>
  )
}
```

```tsx
// components/product-actions.tsx
"use client"
import { Button } from "@/components/ui/button"
import { useTransition } from "react"

type Props = {
  productId: string
  deleteAction: (id: string) => Promise<void>
}

export function ProductActions({ productId, deleteAction }: Props) {
  const [pending, start] = useTransition()
  return (
    <Button
      variant="destructive"
      disabled={pending}
      onClick={() => start(() => deleteAction(productId))}
    >
      {pending ? "Deleting..." : "Delete"}
    </Button>
  )
}
```

### 2.3 Validator verdict on the corrected tree

```
RSC Boundary Audit : my-app

[1] components.json rsc flag       :  PASS  (rsc:true matches framework=app-router)
[2] Client primitive directives    :  PASS
[2b] RSC-safe over-clientification :  PASS
[3] Layout/page/template not client:  PASS
[4] Directive well-formedness      :  PASS  (3 directives valid)
[5] Provider wrappers              :  PASS  (ThemeProvider lives in client wrapper)
[6] Boundary props                 :  PASS  ("use server" action passed instead of inline function)

Verdict : PASS.
```

Three structural changes resolved all four defects :

1. Moved `"use client"` from `app/layout.tsx` to
   `components/theme-provider.tsx`.
2. Restored `"use client"` on `components/ui/dialog.tsx` (and sheet,
   carousel, ...) via `shadcn add dialog --overwrite` and similar.
3. Replaced the inline `onDelete={() => ...}` with a Server Action
   imported from `./actions.ts` (the `"use server"` file).

## 3. Canonical Server-Shell + Client-Island Reference

The shape every App Router page should follow. The validator uses
this as the gold standard against which it judges a real project.

```tsx
// app/dashboard/page.tsx (SERVER ; renders Card from RSC-safe shadcn)
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card"
import { Badge } from "@/components/ui/badge"
import { DashboardActions } from "./dashboard-actions"     // client island
import { db } from "@/lib/db"

export default async function DashboardPage() {
  const stats = await db.dashboard.summary()
  return (
    <div className="grid gap-4 md:grid-cols-3">
      {stats.map((s) => (
        <Card key={s.key}>
          <CardHeader>
            <CardTitle>{s.label}</CardTitle>
            <Badge variant="secondary">{s.delta}</Badge>
          </CardHeader>
          <CardContent>
            <p className="text-2xl font-semibold">{s.value}</p>
            <DashboardActions statKey={s.key} />              {/* client island */}
          </CardContent>
        </Card>
      ))}
    </div>
  )
}
```

```tsx
// app/dashboard/dashboard-actions.tsx (CLIENT island)
"use client"
import { useState } from "react"
import { Button } from "@/components/ui/button"
import { Dialog, DialogTrigger, DialogContent } from "@/components/ui/dialog"

export function DashboardActions({ statKey }: { statKey: string }) {
  const [open, setOpen] = useState(false)
  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <DialogTrigger asChild>
        <Button size="sm" variant="ghost">Details</Button>
      </DialogTrigger>
      <DialogContent>{/* detail body */}</DialogContent>
    </Dialog>
  )
}
```

Properties the validator checks :

- `app/dashboard/page.tsx` does NOT start with `"use client"` (rule 3 PASS).
- `app/dashboard/dashboard-actions.tsx` starts with `"use client"`
  (rule 2 PASS for Dialog).
- Only the serialisable `statKey: string` crosses the boundary
  (rule 6 PASS).
- `components/ui/card.tsx`, `badge.tsx`, `button.tsx` do not carry the
  directive (rule 2b PASS).
- `components/ui/dialog.tsx` carries the directive (rule 2 PASS).

## 4. Worked Trace : Step-By-Step Through a Single File

Input : `app/settings/page.tsx`. Lines :

```tsx
import { Sidebar, SidebarTrigger } from "@/components/ui/sidebar"
import { ThemeToggle } from "@/components/theme-toggle"

export default function SettingsPage() {
  return (
    <div>
      <Sidebar />
      <ThemeToggle onToggle={() => console.log("toggled")} />
    </div>
  )
}
```

Validator trace :

1. Read first non-blank line : `import { Sidebar, ... }`. NOT
   `"use client"`. File is classified server.
2. Scan imports : `@/components/ui/sidebar` -> Sidebar is in the
   CLIENT-REQUIRED list. **FAIL rule 2.**
3. Cross-check : the file is `app/settings/page.tsx` (a route segment
   `page.tsx`). Rule 3 applies : it must NOT have the directive.
   Currently does not -> rule 3 PASS (intentional).
4. Scan JSX children for prop violations : `<ThemeToggle
   onToggle={() => ...}>`. Inline arrow function. **FAIL rule 6
   (candidate)**.

Verdict for this file :

```
[2] app/settings/page.tsx        FAIL  (imports Sidebar, needs client wrapper extraction)
[6] app/settings/page.tsx:8      FAIL  (inline-arrow onToggle to <ThemeToggle>)
```

Remediation :

```tsx
// app/settings/page.tsx (server, fixed)
import { SettingsShell } from "./settings-shell"
import { ThemeToggle } from "@/components/theme-toggle"

export default function SettingsPage() {
  return <SettingsShell><ThemeToggle /></SettingsShell>
}
```

```tsx
// app/settings/settings-shell.tsx (client)
"use client"
import { Sidebar, SidebarTrigger } from "@/components/ui/sidebar"
import type * as React from "react"

export function SettingsShell({ children }: { children: React.ReactNode }) {
  return (
    <div>
      <Sidebar />
      {children}
    </div>
  )
}
```

`<ThemeToggle>` is rebuilt as a self-contained client component that
manages its own state ; the parent server page no longer passes an
inline function.
